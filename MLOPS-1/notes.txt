Phase-2: Dockerize ML applications
===================================

Traditional ML Flow:
Datase
Production ready ML application
Saved model -> Python App -> REST API -> Automated Test -> Docker Container -> CI/CD
Can be tested, deployed, accessed by clients and maintained consistently

File data type only supports "string"

Why we need Docker?
- Imagine rightnow ML application is working on your macbook , but fails on anither 
engineer laptop that runs it on a Linux/Windows server

Possible reasons of failure:
- Different Python versions
- Differnet versions of scikit-learn or FastAPI
- Missing Python packages
- Different OS dependencies

Docekr helps package your application code, runtime, dependencies, and startup
instructions into a standordized image

4 Major requirements:
- Dockerfile - Instructions for packaging the ML application 
- Image - packaged reusable applicaiton artifact
- Container - Running instance of the image
- Port mapping - Makes the API inside the container accessible form your system

Commands for Docker:
1. docker ps = print all running containers
2. docker ps -a = print all containers (running and stopped)
3. docker build -t cse-mlops . 
= build docker image
= -t = tag = name of the image
4. docekr images = List locally available docker images
5. Start the container:
docker run -d --name iris-ml-api -p 8000:8000 cse-mlops

Phase-4: MLFlow - Experiment Tracking and Model Registery 
=========================================================

Why do we need MLFlow?
- Imagine you train a model multiple times, changing the parameters or dataset versions 
- Without experiment tracking you might end up with files like model_v1.joblib ,model_v2.joblib,
model_v3.joblib ,model_final.joblib 
- MLFlow helps maintain that record

Training experiments 
- Model parameters, dataset details and evaluation results 

MLFlow Tracking
- Records parameters, metrics, run information and model artifacts

MLflow Model Registery
- Organize midel versions, metadata and lifecycle management

Deployment pipeline
- Select, validate and deploy approved model versions

4 major concepts:
- Experiment - collection of related training runs
- Run - one execution of training with specific parameters and results
- Artifact - saved file produced by a run, such as trained model or evaluation report
- Model Registery - managed catalog of registered models and their versions

Install MLFLow 
pip install MLflow

mlflow server --backend-store-uri sqlite:///mlflow.db --host 127.0.0.1 --port 5000
